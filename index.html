Evidence requirements

Long-term research

Business quality (25), financial strength (20), growth (20), valuation (20), governance and risk (15). Each score requires verified underlying evidence, dates and calculations.

Swing research

Trend (25), momentum (20), volume/liquidity (15), entry setup (20), risk/reward (20). Requires adjusted OHLCV, calculated indicators and an invalidation level.

Potential Investment

Only after financial or technical verification, reconciled ratios, documented downside, strategy suitability and quality review.

Avoid for Now

Only when a specific, evidenced red flag or unsuitable risk/reward is documented. Missing data must instead remain Insufficient Evidence.

Market Evidence Workbench · v2.1

Import a public, non-sensitive market evidence CSV. The file is processed locally in your browser. No automatic market data is fetched, and imported claims are not independently verified. This is not a live scanner.

Required columns: symbol, as_of, close, eps, source_url, source_date. Dates must be YYYY-MM-DD. Close and EPS must be positive numbers. Source URLs must begin with https://. P/E is calculated as close ÷ EPS, but only if both values are for a compatible share and earnings basis.

Research integrity gate

Imported values are user-supplied and unverified until reconciled with the original dated filings and price records. EPS must be attributable to ordinary shareholders and reflect the correct share count. P/E is not computed for zero or negative EPS. No fundamental or swing score is assigned automatically.

Primary sources: NSE market reports · NSE financial results · NSE announcements.

Use licensed market data for any future automatic feed. Do not assume exchange data can be redistributed through a public site.

Zerodha Kite — proposed read-only integration

Not connected

No holdings or positions are imported in this prototype. No credentials or access tokens should be entered here.

  1. Register a Kite Connect application through the official Zerodha developer portal when ready.
  2. Use Zerodha's official login redirect and exchange the request token in a dedicated backend.
  3. Keep Kite API secrets and access tokens server-side in a secrets manager. Never expose them to browser JavaScript or an AI model.
  4. Expose narrowly scoped backend endpoints for holdings, positions and instrument metadata; deny order routes at the gateway and application layers.
  5. Keep the AI research service separate from the broker data gateway, and test prompt injection, exfiltration and cross-account access.
Kite Connect credentials may have trading capabilities even if the UI is read-only. This design therefore requires server-side isolation and deny-by-default controls; it does not claim the broker-issued token itself is read-only.

Production security release gates

  • Threat model and architecture review
  • Authenticated HTTPS hosting with MFA or passkeys
  • Server-side Kite secret storage and strict endpoint allowlists
  • Dependency scanning, CSP, input validation and rate limits
  • Prompt-injection and exfiltration red-team tests
  • Independent review before connecting real brokerage data

A static prototype is not evidence that the future integrated platform is secure. No system can promise immunity from all AI-enabled attacks.
